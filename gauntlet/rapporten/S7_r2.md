## FAILs

### F1 (middel) `Engine.ontgrendeld` negeert `casusId` van een Logging-record
Reproductie (`S7_r2_scripts/probe.js`, regel "ontgrendeld andere pseudoniem/casus niet gefilterd"):
```
Logging.bewaar({pseudoniem:"anderen", casusId:"andere-casus", episodeId:"E1", geschonden:[], tijdlijn:[]});
Engine.ontgrendeld(CASUSSEN[0], "E2", Logging.alle())   // geeft true, moet false zijn
```
Oorzaak: `gehaaldSet` leest alleen `episodeId` en `geschonden`/`poortGehaald`; het record bevat wel `casusId` (contract §6), maar de engine gebruikt het niet. Zodra er een tweede casus met dezelfde episode-id's bestaat (M6: "nieuwe casus = alleen nieuwe data"), gaat daar de eerste episode open door pogingen op een andere casus.
Reparatie: geef `gehaaldSet` de casus mee (`gehaaldSet(gehaald, casus.id)`) en sla een record over als `x.casusId != null && x.casusId !== casus.id`; zet een test erbij (record met ander `casusId` en `geschonden: []` ontgrendelt niets) en een mutatie-controle. Opmerking voor LEAD/S9: filteren op pseudoniem moet de UI doen (de API heeft geen pseudoniem-parameter); documenteer dat in de aanroep (`Logging.alle()` gefilterd per pseudoniem meegeven), anders opent de poging van student A de episode voor student B.

### F2 (laag-middel) `Engine.volgendeDag` is niet atomisch: een fout midden in de berekening laat de state half bijgewerkt achter
Reproductie: `node S7_r2_scripts/probe2.js` (maakt de `als`-voorwaarde van V8 in E3.weefselinvasie kapot met een onbekend predicaat; speelt V8 G1 G2 | G3, dan volgendeDag):
```
FOUT: Onbekend predicaat 'bestaatniet'.
voor:  { dag: 2, kl: 3, geb: 0, wacht: 1, toest: ['cystitis'] }
na:    { dag: 3, kl: 3, geb: 1, wacht: 0, toest: ['cystitis','weefselinvasie'] }   // dag + gebeurtenis al toegepast, klachten[3] ontbreekt
tweede poging: geen fout, dag 4 (een dag is overgeslagen, klachten[3] blijft leeg)
```
Oorzaak: `volgendeDag` roept `pasGebeurtenissenToe`, zet `state.dag`/`actiesOver` en berekent pas daarna `berekenKlachten`. Een uitzondering (kapotte datapredicaat) laat dus de nieuwe dag, de nieuwe toestand en geleegde `wachtend` achter zonder klachtenstatus; een tweede klik slaat een dag over.
Reparatie: bereken eerst alles op een kopie (of werk in de volgorde: bepaal nieuwe toestand/gebeurtenissen op een `kopie(state)`-achtig tussenobject, bereken `berekenKlachten`, en schrijf pas aan het eind naar `state`), of zet bij een uitzondering de oude waarden terug (`dag`, `actiesOver`, `toestanden`, `sets`, `gebeurtenissen`, `wachtend`). Test: kapotte `als` in een fixture, `volgendeDag` gooit, `JSON.stringify(state)` identiek aan vóór de aanroep.
