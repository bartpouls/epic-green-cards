## FAILs

### F1. `null` waar een id verwacht wordt is een stille false/true (typfout stil, regressieklasse r1)
Reproductie (`S5_r4_scripts/probe1.js`):
```
{p:"gespeeld",     kaart:null}     -> false (geen fout)
{p:"nietGespeeld", kaart:null}     -> true  (altijd waar!)
{p:"gespeeld",     start:null}     -> false
{p:"gestart",      middel:null}    -> false
{p:"actief",       middel:null}    -> false
{p:"gespeeld", kaart:"Q1", optieNiet:null} -> true (stil genegeerd)
```
Oorzaak: `lijst(null)` geeft `[]`; `valLijstTekst`/`valNietLeeg` kijken daarna naar niets, en `valNietLeeg` toetst alleen `Array.isArray(x) && x.length === 0`. `vereis` kijkt alleen naar `undefined`. PREDICATEN.md ('een veld van het verkeerde type ... ids (tekst)') belooft hier een fout.
Reparatie: in `valLijstTekst(x, wat)` eerst `if (x === null) fout("'" + wat + "' mag niet null zijn ...")` (voor `kaart`, `start`, `middel`, `optieNiet`; `doel` en `optie` blijven `null`-toegestaan), en in `VAL.gestart` dezelfde controle voor `middel`. Voeg tests toe voor alle zes de gevallen hierboven, plus een mutatietest op die regel. Overweeg ook: `opDagRelatief` met `van > tot` (nu stil false, `van:3, tot:1`) als fout te melden, en `binnenBeurten`/`binnenBeurtenNaKaart` met niet-geheel of negatief `n`.

### F2. `evalueer` met een ctx zonder structuur geeft stil false (verkeerd argument wordt niet gezien)
```
evalueer({p:"gespeeld",kaart:"Q1"}, {})         -> false
evalueer({p:"gespeeld",kaart:"Q1"}, casus)      -> false   (casus in plaats van ctx doorgegeven)
evalueer({p:"waarheid",waarde:true}, {})        -> true
```
Alleen `null`, `undefined`, arrays en strings geven de Nederlandse fout 'Er is geen geldige context'. `valideer` herkent zelf al een echte ctx (`Array.isArray(ctx.tijdlijn) && isObj(ctx.episode) && typeof ctx.status === "function"`). Voor S6 is dit de plek waar een verwisseling (casus, episode of state i.p.v. ctx) onopgemerkt blijft.
Reparatie: in `valideerPred`/`valTeller` dezelfde check als `valideer` gebruiken (`isCtx(ctx)`), en de fout 'ctx komt uit Predicaten.maakContext' geven. Test: `evalueer(p, {})`, `evalueer(p, casus)` en `evalueer(p, state)` met `state.tijdlijn` maar zonder `status` geven een fout. Let op: `waarheid` heeft geen ctx nodig; kies bewust (aanbevolen: ook daar vragen om een echte ctx, dat is consequent).

Dit is geen P-criterium van S5 en geen fout in de regeltaal, maar S5 is de oorzaak van de vermenigvuldiging en de reparatie is klein, daarom als FAIL genoteerd (contract par. 7: de tests moeten headless in Node draaien, een run van 110 s maakt het gauntlet-proces onbruikbaar).

**Meting (`S5_r4_scripts/prof3.js`, `prof.js`, `plain.js`, `browser.js`, `perf_plain.js`):**

**Reparatie-aanwijzing (getest op een kopie in de scratchpad):**

Niet doen, tenzij je cachet op een bevroren (diep `Object.freeze`) predicaat plus identiteit van episode én casus; dan kan het niet muteren. Voor de huidige aantallen is het niet nodig.

## Interface-naden met S6 en S7
- **S6 Evaluatie** (bestaat nog niet): moet `Predicaten.maakContext(casus, episode, state)` gebruiken, waarbij `state.klachten[i]` `{dag,status}` heeft (de engine zet `klachten[0] = {dag:0,...}`; ok) en `state.gebeurtenissen` `{id,dag}` (de dag waarop de banner verscheen; `naVolg` wordt niet gebruikt). De `perKeer`-teller in E2 (`{t:"gespeeld", kaart:"B1", terwijlKlachten:"af"}`) moet via `Predicaten.tel` lopen; die valideert foutloos. Laat Evaluatie bij het laden `Predicaten.valideer` over alle predicaten uit de data draaien (385 stuks, nu allemaal geldig), zodat een datafout meteen en niet pas in een route verschijnt. Elke fout is een `Error` met Nederlandse tekst; Evaluatie moet die niet inslikken (de engine heeft `atomisch()` en slikt niets). Zie F2: geef ctx altijd via `maakContext`.
- **Engine (S3/S4)**: roept `evalueer({p:"actief", middel:k, op:{dag:d}}, ctx)` aan met `d-1` (dag 0 bij dag 1: geeft false, geen fout) en `evalueer` op `doelen[].vereist` en `werkzaamheid[].als`. Die gaan goed. De engine maakt per aanroep een nieuwe ctx (kopieert de lijsten): goedkoop genoeg.
- **S7 (overzicht.html)**: `Predicaten` heeft geen functie die een predicaat in leesbare tekst omzet; S7 moet de JSON-AST zelf weergeven (er is `Predicaten.namen`). Geen conflict met het contract (par. 3 noemt alleen 'leesbaar').
- Gebeurtenis-id's worden alleen gecontroleerd als `episode.gebeurtenissen` bestaat en niet leeg is (E1 heeft er geen): een gebeurtenisverwijzing in een E1-predicaat zou dus nooit een fout geven. Bewuste, gedocumenteerde keuze; noem het in de S6-test.
